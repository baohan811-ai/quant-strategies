# PJ1 量化研究与策略维护

在不牺牲 point-in-time 正确性、数据完整性和可审计性的前提下，完成 PJ1 的研究、诊断或实现任务。遵守项目根目录 `AGENTS.md`；本 Skill 不扩大用户对 Wind 请求、正式策略修改或外部交易操作的授权。

## 获取项目上下文

1. 先阅读项目根目录 `PROJECT_NOTES.md` 的“重要提醒”。
2. 再按任务读取相关章节：
   - 基本面、估值和因子：搜索“SQLite 基本面数据库”“ROE 后视镜错误复盘”。
   - 行情、复权、信号变化：搜索“SQLite 行情数据库”“原始行情与复权因子迁移”。
   - 中证800回测：搜索“股票池/指数历史成分快照”和对应策略名称。
   - Wind 补库：同时读取相关数据库章节和完成度、额度规则。
3. 将带日期的进度、行数、状态和策略结果视为历史记录；通过代码、数据库元数据和最新输出核验当前事实。
4. 检查 `git status`，识别用户已有改动，只触碰当前任务需要的文件。

## 识别任务边界

- 明确目标是解释、诊断、实验、正式修改、补数还是运行执行版。
- 确认目标文件属于研究脚本、开发版还是执行版，并找到它复用的共享模块、数据库和输出路径。
- 诊断只读查因；修复或正式落地必须来自用户请求。不要用一次研究请求推导出修改生产脚本、调用大额 Wind 或执行真实交易的权限。
- “如果效果更好就修改”属于条件式落地授权；当目标文件、参数联动方式和判定标准都明确时，满足条件后可在同一任务中落地，不必机械地再次确认。若任一歧义会实质改变策略，则先澄清。

## 数据语义审计

- 对每个历史因子区分报告期、公告日、策略可用日、信号日、查询日和数据版本。
- 财务因子要求保留 `value + report_period + announcement_date + available_date + source/mode`，并断言 `available_date <= signal_date`；违规时停止正式回测。
- 对供应商便捷派生字段先做最小可证伪检查：选择已知公告样本比较公告前后可见性，并在需要时比较不同抓取日的历史值稳定性。
- 指数或股票池策略优先使用历史成分快照。若历史快照未接入或覆盖不全，明确披露幸存者偏差，不把当前成分回看历史包装成无偏回测。
- 记录缺失值处理、异常值处理、行业分类版本、基准和成本假设，使结果可以复现。

## 行情、复权与交易可行性

- A 股行情通过 `执行中策略/脚本/维护工具/local_market_db.py` 的共享接口读取，让共享层选择当前激活且 `ready` 的底层模型；不要在策略内自行直查底层行情表。
- 按目标股票池、所需字段和时间层级检查覆盖率，不能只看全库最大日期或用另一个股票池的完整性代替。
- SQLite 只使用完整 EOD。盘中数据需要时通过实时接口临时加入内存；正式回测保持完整 EOD 对完整 EOD。
- 原始价、复权因子和公司行为使用同一版本，抽样核对供应商前复权结果与因子变化。不得拼接不同抓取时点的滚动前复权窗口。
- 将数据库重算结果与真实成交台账分开：历史数据修订可以改变研究回放和新信号，不能删除或重写已经成交的持仓事实。
- 审计信号日、下单日和成交价的时间关系，同时检查停牌、退市、涨跌停、成交量、手续费、滑点和资金占用。

## Wind 请求与补库

1. 在任何大规模请求前估算：数据内容、起止日期、标的数、字段数、预计 cells、批次和校验方式。
2. 把估算与拆分方案告诉用户，由用户给出本次额度；未获得确认不启动大额补抓，也不自行降低准确性换取完成。
3. 确认 WindPy 登录和终端可用，再按最近数据优先、可断点续跑的方式执行已授权批次。
4. 对限额、权限失败、空结果和覆盖不足保留明确状态。稳定整批空值按 `PROJECT_NOTES.md` 的现行规则处理，不无限重试。
5. 完成后给出完整完成度表和剩余缺口；只有通过覆盖率、时间语义和抽样对数的版本才能标记为 `ready`。

## 回测与参数优化

1. 固定基准、区间、数据截止日、股票池版本、行情/基本面版本、调仓和成本口径。
2. 在查看候选结果前明确主要评价指标和不可接受的退化；用户未指定时，优先采用已记录且仍适用的偏好。若没有可依据的偏好且判据将直接触发正式落地，先请用户确认；纯研究任务可以给出并披露合理判据。不能事后挑选最有利指标。
3. 调整单项评分权重时，明确其它权重如何联动并保证合计为 1；不要静默改变未说明的因子权重。
4. 先复现当前基准，再对候选方案做可复现的枚举或网格扫描，保存关键中间结果和完整排序。
5. 同时比较年化收益、夏普、最大回撤、换手、交易数、成本敏感性、空仓或资金利用率；不要只按单一收益指标排序。
6. 对候选参数做起始日扰动、参数邻域、稳定平台、邻域最差值和样本外检查。优先选择稳定区域内的保守点，不选孤立尖峰。
7. 若修正了未来函数、复权、股票池或其它数据口径，重跑旧策略并明确哪些旧结论已失效，避免跨口径直接比较。

## 生产落地与验证

- 实验代码和一次性探测放 `/tmp`；用户要求保留时才在项目内新增正式或长期维护文件。
- 先形成实验对比和风险结论，再按用户的明确授权修改执行版；已有的条件式授权满足判据时可直接落地。保留正式脚本已有的安全门槛、日志和数据诊断，不把参数扫描过程塞入日常输出，除非用户要求。
- 修改后至少做语法或导入检查、相关小范围测试、数据质量门槛检查和关键输出核验；高风险改动再做基准回归。
- Excel 或其它报告沿用目标脚本当前的表结构和视觉规范，核对数据截止日、列顺序、单位、小数位、冻结窗格、缩放、筛选、高亮和列宽；只把特定工作簿的格式要求固化到对应脚本，不泛化到所有输出。

## 异常诊断顺序

出现最新信号、持仓数量或历史结果异常时，依次排查：

1. 数据截止日、交易日历和盘中/完整 EOD 混用。
2. 目标股票池的逐日覆盖率与历史成分快照。
3. 单票 Wind 原始数据和本地缓存的逐日差异。
4. 复权锚点、公司行为和不同数据版本的历史重算。
5. 策略过滤器、排序、缓冲区、资金分配、整数股数和成交约束。
6. 跨市场任务是否显式使用对应交易日历并与 A 股权威库隔离。

报告原因时区分已证实事实、合理推断和仍需验证的假设；若用户只要求诊断，停在证据充分的结论与可选修复方案。
